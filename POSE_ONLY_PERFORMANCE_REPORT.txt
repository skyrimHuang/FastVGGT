2. 模块级别性能分解
═══════════════════════════════════════════════════════════════════════════════════

[单独测试各模块耗时] (30次运行平均值)

  📦 Aggregator (聚合器 = 补丁嵌入 + Transformer块)
     • 耗时: 1238.51 ms  (占全模型 88.1%)
     • 范围: [1217.64 ms, 1326.69 ms]
     • 每帧: 123.85 ms/frame
     
  🎥 Camera Head (相机位姿估计头)
     • 耗时: 11.12 ms  (占全模型 0.8%)
     • 范围: [11.29 ms, 12.59 ms]
     • 每帧: 1.11 ms/frame
     
  🌊 Depth Head (深度估计头) ← 被屏蔽的模块
     • 耗时: 82.09 ms  (占全模型 5.8%)
     • 范围: [84.25 ms, 88.11 ms]
     • 每帧: 8.21 ms/frame

[模块求和 vs 完整模型]
  • 各模块求和:     1238.51 + 11.12 + 82.09 = 1331.73 ms
  • 完整模型实际:   1406.55 ms
  • 额外开销:       74.82 ms (5.3%)
  • 开销说明:       主要来自模块间的同步、数据依赖、GPU通信等

3. 仅位姿模式分析
═══════════════════════════════════════════════════════════════════════════════════

[计算方式]
  • 完整模型 = Aggregator + Camera Head + Depth Head + 开销
  • 仅位姿   = Aggregator + Camera Head
  • 仅位姿时间 = 1238.51 + 11.12 = 1249.64 ms

[性能获益]
  ✅ 加速倍数:     1406.55 / 1249.64 = 1.13x
  ✅ 时间节省:     1406.55 - 1249.64 = 156.91 ms / batch
  ✅ 每帧节省:     156.91 / 10 = 15.691 ms/frame  
  ✅ 速度提升:     (1 - 1/1.13) × 100 = 11.2%

[真实帧率提升]
  • 完整模型: 7.11 FPS
  • 仅位姿:   8.00 FPS  
  • 提升:     0.89 FPS (12.5% 帧率提升)

5. 瓶颈分析
═══════════════════════════════════════════════════════════════════════════════════

[主要瓶颈：Aggregator 占 88.1% 的计算 (1238.51ms)]

  Aggregator 包含的计算 (在优化后的aggregator.py中):
    1️⃣  补丁嵌入 (Patch Embedding): DinoV2 ViT-L 特征提取
    2️⃣  Frame Attention Blocks: 24 层 (处理单帧特征)
    3️⃣  Global Attention Blocks: 24 层 (处理全局特征)
    4️⃣  位置编码 (RoPE): 旋转位置嵌入
    5️⃣  令牌合并 (Token Merging): 动态合并重复令牌

[为什么屏蔽Depth Head收益有限？]
  • Depth Head 只占 5.8% (82.09ms)，但仅能获得 11.2% 加速
  • 额外 74.82ms 开销来自: Depth Head 的数据处理与GPU通信
  • 真正的瓶颈是 Transformer 计算 (占 88.1%)

6. 优化建议 (后续工作方向)
═══════════════════════════════════════════════════════════════════════════════════

[短期优化: 获得 2-3x 加速]
  1️⃣  模型量化 (Model Quantization)
      • INT8 量化: 预期 1.8-2.2x 加速
      • FP16 混合精度: 已使用 (当前方案)
      
  2️⃣  结构化剪枝 (Structured Pruning)
      • 减少 Transformer 层数 (24→12): ~2x 加速
      • 减少嵌入维度 (1024→512): ~1.5x 加速
      
  3️⃣  Token Dynamic Merging 优化
      • 更激进的令牌合并比例: ~1.3x 加速

[中期优化: 获得 5-10x 加速]
  4️⃣  替换主干网络 (Backbone)
      • ViT-L14 → ViT-B14: ~2-3x 加速
      • DeiT → MobileViT: ~3-5x 加速
      
  5️⃣  蒸馏 (Knowledge Distillation)
      • 使用完整模型蒸馏轻量级版本: ~2-3x 加速

[硬件优化]
  6️⃣  GPU 批处理
      • 批处理多个输入: 提高吞吐量 (但延迟不变)
      
  7️⃣  移动部署
      • TensorRT 优化: ~1.5-2x 加速
      • Mobile GPU (高通 Adreno): ~1-2x 加速

7. 结论
═══════════════════════════════════════════════════════════════════════════════════

✅ VGGT 屏蔽 Depth Head 后的性能表现:

  • 推理延迟: 124.96 ms/frame (相对完整模型降低 11.2%)
  • 帧率提升: 从 7.11 FPS → 8.00 FPS (涨幅 12.5%)
  • 内存节省: 从 8151 MB → 6759 MB (节省 1392 MB, 17%)
  • 实时性:   **仍不满足 AR 要求** (需要 < 33.33ms)

❌ AR实时应用当前状态:

  即使完全禁用 Depth 模块，VGGT 仍需要 **3.75-4.22x 的加速** 才能运行 30-60 FPS AR。
  根本问题在于 Aggregator 的 Transformer 计算（88.1% 的耗时）。

🎯 推荐使用场景:

  ✓ 离线后处理 / 非实时应用
  ✓ GPU 性能充足的专业设备 (工作站/服务器)
  ✓ 需要高精度位姿 + 深度的应用
  
  ✗ 实时 AR (手机/平板)
  ✗ 低功耗设备
  ✗ 边缘计算部署
